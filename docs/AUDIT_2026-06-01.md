# CareCircle — Comprehensive Codebase & Project Audit

**Date:** 2026-06-01
**Scope:** Full iOS app (`CareCircle/`, ~265 Swift files / ~34k LOC) + Node backend (`backend/`, ~90 TS files / ~13k LOC), CI/CD, dependencies, architecture, security, and product.
**Method:** 16 parallel deep-dive review agents (one per subsystem), 3 feature-strategy agents (one per strategic wedge), and one adversarial completeness-and-correctness critic that re-read the cited code to confirm or refute the top findings. Every finding below is anchored to `file:line` and quoted evidence. This is a read-only audit — no code was changed.

---

## 1. Executive summary

CareCircle is, component-by-component, a well-engineered codebase. The backend is genuinely strong: correct FORCE-RLS tenant isolation, envelope encryption, append-only audit log, textbook refresh-token rotation with reuse detection, clean Fastify encapsulation, fail-fast config validation, and 20 integration suites including an RLS isolation test. The iOS app is disciplined: zero force-unwraps in production, typed errors, constructor/Environment DI, a CloudKit-correct SwiftData model graph (every attribute optional/defaulted, every inverse declared, no `@Attribute(.unique)`), conservative on-device health analytics, and an exemplary SOS arm/cancel UX.

**The problem is not the parts — it's the seam between them, and the gate that should have caught it.** The audit's dominant finding is that **the entire iOS ↔ backend data plane is non-functional end-to-end**, through four independent, compounding breaks, and **CI is red on every run so none of it is caught before merge to `main`.** In-family CloudKit sharing still works (and the dual-write migration was always flagged as a future task), but several *shipped, user-facing* features — most seriously **SOS** and all **remote push** — were built on top of the unfinished backend path and silently no-op in production.

**Overall grade: C+ / "at-risk".** The engineering quality is B+/A-, but it is undermined by a non-working data/notification plane on safety-critical paths and a decorative CI that provides zero protection. None of the four headline breaks is hard to fix; they are wiring gaps, not design flaws. Fix the data plane and the CI gate and this is a strong codebase.

## 2. The headline: the data + notification plane is broken end-to-end

Four independent breaks combine so that **no iOS-originated write reaches the backend, and no backend push reaches a device.** Each was verified against the actual code.

### C1 — `/v1/sync/batch` is a write-only dead-letter; iOS then deletes the local op
- `backend/apps/api/src/routes/sync.ts:14-28` — the entire handler is `INSERT INTO pending_operations (...) ON CONFLICT (user_id, client_op_id) DO NOTHING RETURNING id`, acking `'queued'`.
- **Verified:** `pending_operations` has exactly one writer (`sync.ts:16`) and one schema definition (`schema.ts:569`) in all of `backend/`. The four BullMQ workers are `push`/`openFda`/`pdf`/`digest` only (`worker/src/main.ts:31-49`) — **nothing consumes the table.** No cron, no `LISTEN`, no projector.
- **Worse than a silent drop:** `SyncEngine.sendChunk` (`CareCircle/Sources/Services/Backend/SyncEngine.swift:390-393`) treats the `'queued'` ack as success and **deletes the local `PendingOperation`**. The write is destroyed on-device *and* never persisted server-side. 13 iOS feature call sites enqueue through this path.

### C2 — SOS routes through C1 and never alerts other caregivers
- `SOSCenter.fire` → `syncEngine.enqueueSOSEventCreate` (`SOSCenter.swift:165`) → op type `create_sos_event` → `/v1/sync/batch` (the dead table). The working route `POST /v1/circles/:circleId/sos` (`sos.ts:9`, which inserts `sos_events`, fires the NOTIFY trigger, and enqueues push) is **never called by iOS** — the app only ever issues `GET` for SOS reconcile.
- The triggering phone does post a correct local `.timeSensitive` notification to *itself* (`SOSCenter.swift:176-188`), so the presser sees confirmation — but **no other circle member is notified through the backend.** The carefully-built notification-retraction/cancel logic is dead because cancel/resolve also never reach the backend (`SOSCenter.cancel` and `markResolved` are local-only).

### C3 — iOS never registers an APNs device token (found by the critic, independently verified)
- **Verified:** zero matches in `CareCircle/Sources` for `registerForRemoteNotifications`, `didRegisterForRemoteNotifications`, `apnsToken`, or any call to `POST /v1/me/devices`. `AppDelegate.swift` only styles the nav bar.
- The push worker (`worker/src/jobs/push.ts:22-35`) sends to rows in the `devices` table keyed on `apns_token`. With no registration, **that table is empty for real users**, so every push job (digests, SOS, future med escalations) delivers to zero devices — a second, independent break in the remote-notification pipeline.

### C4 — backend SOS push demands a Critical Alert the app isn't entitled to
- `sos.ts:50` hard-codes `critical: true` → `apns.ts:59-72` sets `sound:{critical:1}` + `interruption-level: critical` + priority 10. The entitlements file has **no** `com.apple.developer.usernotifications.critical-alerts` key, so APNs would reject the payload with no fallback to `time-sensitive`. (Latent today behind C2/C3, but it violates SPEC rule #7's "must degrade gracefully" the moment those are fixed.)

### C5 — CI is red on every run; `main` merges anyway
- **Verified** against `gh run list` and the workflow files:
  - Backend lint runs `eslint . --max-warnings=0` but **eslint is not a dependency and there is no eslint config** → fails.
  - `apps/api/tsconfig.json` sets `rootDir: "src"` with `include: ["src/**/*","test/**/*"]` → TS6059 on every test file → typecheck fails.
  - `backend.yml:95-99` runs `pnpm --filter @carecircle/db prisma:generate` + `migrate` — **Prisma scripts on a Drizzle codebase** (the real migrator is `@carecircle/migrator`). `pnpm --filter` exits 0 on a missing script, so the steps go green while doing nothing; tests then run against an unmigrated DB and error.
  - `ios.yml:28,66` pins Xcode 16 + an iPhone 16 Pro Max / iOS 18 destination the `macos-15` runner can't satisfy → build fails.
- Net: the 20 backend suites (incl. RLS isolation) never run green in CI, Dependabot PRs can't merge, and regressions land unchecked.

**Read these five together:** the backend is correct and tested, the iOS app is correct locally, but the bridge is severed in both directions and the safety net that should have flagged it is down. This is the single most important thing to fix, and it is mostly wiring.

> **Calibration note:** the dual-write iOS→backend migration was always documented as incomplete (CLAUDE.md). What elevates this from "known TODO" to "at-risk" is that (a) iOS *destroys* local ops on a fake-success ack, (b) **shipped safety features (SOS, escalation, push) were built on the unfinished path and appear functional but aren't**, and (c) CI cannot catch any of it. In-family CloudKit sharing is unaffected and continues to work.

## 3. CRITICAL & HIGH findings (consolidated)

### CRITICAL (P0)

1. **C1 — dead-letter sync** — `sync.ts:14-28`, `SyncEngine.swift:390-393`. *Fix:* build the `sync-projector` worker that drains `pending_operations` into domain tables (idempotent on `client_op_id`); only delete the local op after a `projected`/`applied` ack, not `queued`.
2. **C2 — SOS never fans out** — `SOSCenter.swift:165`. *Fix:* call `POST /v1/circles/:circleId/sos` directly at fire time (own immediate request + retry, not batched); wire `cancel()`/`markResolved()` to the backend cancel route.
3. **C3 — no APNs device-token registration** — entire iOS app. *Fix:* `registerForRemoteNotifications()`, implement the AppDelegate token callbacks, POST the token to `/v1/me/devices` on launch/auth.
4. **C5 — CI fully red** — `backend.yml`, `ios.yml`. *Fix:* add eslint + config; fix `tsconfig` rootDir; replace the Prisma steps with `@carecircle/migrator`; align the iOS runner/destination to Xcode 26; then enable branch protection requiring green checks.
5. **Zero iOS tests across 34k LOC, incl. dose/SOS/crypto** — `CareCircleTests/{Unit,Integration}` empty. *Fix:* create the Unit Testing Bundle target (Xcode UI — **requires you**), then unit-test the pure logic first: dose-state transitions, reminder scheduling, SOS, AES-GCM key wrap/unwrap, `PHIRedactor`, schedule math. Add a `test` action to `ios.yml`.

> **Re-graded (was reported CRITICAL): real drug-interaction checking.** The critic confirmed `InteractionChecker.swift` *and its UI* honestly disclaim that it only checks same-ingredient overlap ("Ingredient overlap is a starting point — it does not replace a pharmacist's interaction check," `PillIdentifierResultView.swift:85`). This is **not** a deceptive-safety defect; it is a **HIGH product gap** — the flagship "Medication Safety" wedge does not yet do real drug-drug/drug-allergy checking. See §6 feature backlog.

### HIGH (P1)

**Notification & medication safety**
- **C4 — critical-alert push with no entitlement / no fallback** — `sos.ts:50`, `apns.ts:59-72`.
- **No missed-critical-dose escalation to other caregivers** — `MedicationReminderScheduler` produces local notifications only; no fan-out. (Depends on C1.)
- **Reminder scheduler caps at 16 requests/med and uses `.default` sound, no interruption level** — `MedicationReminderScheduler.swift:22-23,109`. Budget the 64 app-wide pending-request ceiling across active meds; set `.timeSensitive`.

**Sync, realtime & E2EE**
- **Realtime socket authorizes once at connect, freezes membership, takes the token in the query string** — `realtime.ts:21-71`. Re-check membership periodically; move the token to a header/subprotocol.
- **Per-circle document keys stored `ThisDeviceOnly` (non-synchronizable)** — `DocumentKeyStore.swift:67,94`; other members/devices can't decrypt shared documents. `forget(circleID:)` (`:113`) has zero callers, so keys aren't dropped when a member leaves.
- **Inbound merge is a stub** ("skip if local store non-empty") — `BackendHydrator.swift:35,241`. No last-writer-wins/`updatedAt` reconciliation; a device never picks up backend changes once it has local rows.

**Database & crypto**
- **Static salt for DEK-wrapping key derivation** — `crypto.ts:41-56` (`scryptSync(masterKey,'carecircle-dek-wrap',32)`). Use a per-deployment random salt stored alongside the wrapped keys.
- **Audit-log RLS policy leaks NULL-circle rows** — `0003_enums_and_audit.sql:48-52` (`USING (circle_id IS NULL OR is_circle_member(circle_id))`). Restrict NULL-circle visibility to service/admin reads.

**Subscriptions / revenue integrity**
- **No server-side entitlement enforcement** — `isPaidStatus()` (`lib/subscriptions.ts:314`) has zero callers; inference/documents/digests routes don't gate on subscription. Add `requireEntitlement(...)` after `requireMembership`.
- **StoreKit notification handling is not actually idempotent** — `applyNotification` does an unconditional UPDATE while claiming "idempotent on notificationUUID"; no dedupe table; out-of-order `EXPIRED` after `DID_RENEW` can wrongly downgrade. Add an `app_store_notifications(notification_uuid PK,...)` ledger + monotonic guard. `STOREKIT_ALLOW_SANDBOX` defaults true and `pickEnvironment` defaults to `Production`.

**Security / privacy**
- **PHI redactor misses nicknames, misspellings, relationship terms, ASR errors** — `PHIRedactor.swift:88-101` only strips exact whole-word known names, yet the docstring promises names never leave the device. Add nickname expansion, relationship-term scrub, and an NER pass; soften the guarantee in docs; consider disabling cloud fallback for high-sensitivity circles.
- **`documents/upload-url` builds the object key from an unsanitized client `filename`** — `documents.ts:22`. Sanitize to `[A-Za-z0-9._-]` or drop the filename from the key.
- **No account deletion or data export (UI or cascading backend)** — `me.ts:53-60` is a non-cascading soft-delete; nothing calls it. **App Store 5.1.1(v) requires in-app deletion**; the spec requires exportable/deletable Care-Recipient data.

**Backend**
- **Worker jobs have no retries/backoff/idempotency/retention** — `worker/src/queues.ts`, all `.add(...)` sites. Transient APNs/openFDA/PDF failures are permanent; completed jobs leak in Redis; duplicate enqueues run twice. Add `defaultJobOptions` + deterministic `jobId`.
- **Route params never validated** — every `:id`/`:circleId` is cast, not parsed → malformed UUID = 500 + error-log spam. Add a shared `z.object({id: uuidSchema})` params parse.

**iOS architecture**
- **`static let shared` singletons reached from production view code** — `AddDocumentView.swift:256-283`, `AppointmentDetailView.swift:24,208`, `RootView.swift:146` (hard-rule-4 violation; the services already have injectable inits).
- **Dead-feature models still in the live CloudKit schema; SimplifiedMode still gates the signed-in root** — `CareCircleApp.swift:117-120` (`ChatMessage`/`DirectThread`/`DirectMessage`), `SignedInRootView.swift:29-34`. Dead UI is fully unreferenced but the models still provision CloudKit record types — and removing them safely needs a migration plan that doesn't exist (below).
- **No `VersionedSchema`/`SchemaMigrationPlan` on the CloudKit-backed store** (found by critic, verified) — `CareCircleApp.swift:98-135` builds one `Schema` with no `migrationPlan:` and a `fatalError` fallback. The first post-launch model change risks bricking existing users' stores.

**Performance**
- **Whole-table `FetchDescriptor<M>()` then filter-in-Swift on `@MainActor`** — `BackendRealtimeUpsert.swift:73`, `BackendHydratorVitals.swift:44-56`, `MedicationOverdueSweeper.swift:19`; no `fetchLimit` anywhere. Add `#Predicate` and use `fetchCount`.
- **Cold-launch fan-out of synchronous sweeps + insights recompute on the main thread** — `RootView.swift:44-84`. Defer behind first paint.
- **pg Pool `max:10`, no `statement_timeout`/`connectionTimeoutMillis`** — `db/src/client.ts:18-30`. A single slow query saturates the pool.

**Accessibility**
- **Fixed `.system(size:)` text below 13pt won't scale to AX5** (~15 text sites, mostly Pulse) — won't grow for the elderly/low-vision target audience.
- **New design tokens adopted only on the Home dashboard** — `Font.CC.*` in 2 files vs `Theme.*` in 78; `Motion`/`Haptic` have zero call sites. Inconsistent Dynamic Type/contrast/motion across screens.
- **Several Pulse animations ignore Reduce Motion** — `PulseHeroCard`, `BedsideMonitorView`, `WellnessRing`. Continuous pulsing/breathing motion is exactly what the setting exists to suppress.

**No remote crash/error telemetry** (found by critic) — no Sentry/Crashlytics/MetricKit anywhere. Combined with the silent failures above, field failures are invisible.

## 4. Selected MEDIUM / LOW findings

- **Sleep dedup key uses `String.hashValue`** (per-process random) — `HealthKitVitalsReader+Sleep.swift:146-156`. Identical nights re-insert duplicate local rows every launch; use a stable SHA-256 digest. Timezone bucketing via `Calendar.current` compounds it for traveling/cross-tz circles.
- **Bedside monitor recomputes full vitals analytics on every 1 Hz clock tick** — `BedsideMonitorView.swift:24-29,75-76`. Memoize on `circle.vitals` change.
- **Invite-code entropy is ~40 biased bits** — `invitations.ts:14-22` (`randomBytes(8)` mapped `% 31`, modulo-biased) gates PHI access with no redemption rate-limit. Use rejection sampling, ≥128 bits.
- **Prompt-injection surface** — transcript concatenated directly into the OpenAI prompt (`inference.ts:155-167`); wrap in a delimited untrusted block. (Blast radius limited by the strict JSON schema.)
- **`PATCH /members/:memberId` allows setting arbitrary roles incl. a second owner** — `members.ts:58-80`; no demotion guard. Confused-deputy within a circle (owner-only), not cross-tenant.
- **SOS location races authorization on first run** — `SOSLocationProvider.swift:49-63`; the first-ever SOS may ship with no coordinates.
- **"Always"/background location can't work** — missing `NSLocationAlwaysAndWhenInUseUsageDescription` + `location` background mode; the advertised wandering-risk tracking silently never functions.
- **Location consent is one global `UserDefaults` bool, not per-circle**; precise coordinates broadcast to all circles; stale pins render identically to live ones.
- **openFDA query is double-encoded** — `openFda.ts:38-43`; med-interaction lookups likely silently return empty.
- **Comments endpoint unpaginated** — `activities.ts:291-296`; a hot post returns an unbounded payload.
- **App-wide `.preferredColorScheme(.light)`** — `CareCircleApp.swift:156` makes the carefully-built dark-mode tokens dead.
- **No localization/i18n** — zero `String(localized:)`; acceptable for US-only v1, document as scope.
- **`new/` untracked dir** is benign design mockups (`DESIGN.md` + PNGs); move into `docs/`.
- **CLAUDE.md drift:** says "Fastify + Prisma / feature-first"; code is Drizzle + routes/services layout. The stale spec directly produced the broken Prisma CI step.

## 5. What's genuinely strong (don't regress these)

- **Backend RLS is real, not theater** — `app_user` default role + `FORCE ROW LEVEL SECURITY` + `is_circle_member()` policies, `withRls` setting `SET LOCAL ROLE` + scoped `set_config` in one transaction (PgBouncer-safe). `app_service` BYPASSRLS used only where justified. The RLS isolation integration test is exactly the right test.
- **Auth** — refresh rotation under `SELECT … FOR UPDATE`, reuse-of-revoked detection that kills the whole session, constant-time login, cross-provider email-collision rejection, mock endpoints hard-gated to non-prod.
- **SwiftData/CloudKit modeling** — clean across all 37 model files (optional/defaulted attrs, single inverses, `.cascade`, no unique constraints). The highest-risk modeling area is defect-free.
- **App composition** — full constructor/Environment DI from `CareCircleApp.init`; `AuthState`/`SyncEngine`/`BackendHydrator` are cohesive, not god objects.
- **On-device-first AI** — `EntityExtractorFactory` correctly prefers Foundation Models on iOS 26+, redacts before any cloud call (single choke point), backend never logs prompt content, real cost controls (timeout, per-user cap, char limit, `temperature:0`, strict schema).
- **Health analytics discipline** — min-sample floors, σ>0 guards, median-not-mean, observational (not prescriptive) copy, disclaimers on every med/vitals surface.
- **SOS UX** — 3 s hold-to-arm + 30 s cancellable countdown, Reduce-Motion aware, 88 pt cancel target.
- **Backend hygiene** — clean typed-error boundary (single 5xx log, no stack leaks), fail-fast Zod config validation, complete graceful shutdown on both processes, keyset pagination + matching partial indexes, presigned MinIO URLs, per-circle DEK caching, Dependabot + CODEOWNERS + committed lockfile + `.env*` correctly gitignored.

## 9. Method & coverage

16 subsystem agents (auth, sync/realtime, CloudKit/E2EE, DB/RLS/crypto, medication safety, security/privacy, subscriptions, concurrency, health/vitals/insights, SOS/location, AI/voice/privacy, backend architecture, iOS architecture/SwiftData, accessibility/design, performance/scalability, testing/CI/deps) + 3 feature-strategy agents (Wedge B, Wedge E+A, growth/infra/B2B) + 1 completeness critic that re-read the cited code, confirmed the top criticals, **down-graded the InteractionChecker finding** (code & UI honestly disclaim DDI), and **surfaced the C3 push-registration break, the missing SwiftData migration plan, the absent crash telemetry, the stub inbound-merge, and the weak invite-code entropy**.
